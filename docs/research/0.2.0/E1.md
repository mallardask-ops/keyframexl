# E1 — Нативний PipeWire: дослідження

Станом на 19.11.2026. Головний висновок: у cpal з'явився справжній
PipeWire-бекенд — не в 0.16 і не в 0.17, а в **0.18.0** (06.06.2026); поточна
версія — **0.18.2** (16.08.2026). Це найдешевший шлях для E1: він зберігає
наш рушій, черги й машину перепідключення, але прибирає і `PIPEWIRE_LATENCY`,
і патч cpal. `pipewire-rs` дає більше контролю (фільтр вузлів, точні імена,
власні властивості стріму), але вимагає власного шару стрімів, часу, xrun і
перепідключення. JACK через `pipewire-jack` нічого не додає до нативного
PipeWire, лише ще один набір залежностей.

---

## Поточний стан

### Як відкривається вихід

Весь шлях — `src/audio.rs`, один хост cpal, і той хост — ALSA.

| Крок | Місце |
| --- | --- |
| `cpal::default_host()` (єдиний хост) | `src/audio.rs:683` |
| Перелік виходів/входів для UI | `src/audio.rs:204-223` |
| Пошук збереженого імені, пошук пристрою `pipewire` | `src/audio.rs:689-696` |
| Порядок спроб: named → `pipewire` → default | `src/audio.rs:330-340`, `701` |
| Вимога F32/2 канали на `cfg.rate` або 48 кГц | `src/audio.rs:709-729` |
| Буфер: вибір користувача, інакше 256, потім 512 | `src/audio.rs:229-247`, `754` |
| `BufferSize::Fixed` у конфіг | `src/audio.rs:756-758` |
| Визначення бекенду за іменем пристрою | `src/audio.rs:269-280`, `759` |
| `PIPEWIRE_LATENCY` перед відкриттям | `src/audio.rs:760-770`, `308-320` |
| Побудова й запуск стріму | `src/audio.rs:861-1028` |

Імена пристроїв — ALSA: `default`, `sysdefault:CARD=…`, `pipewire`, `pulse`,
`hw:…`. Тому `detect_backend` — це евристика за підрядком: `default` і
`sysdefault` вважаються PipeWire, лише якщо існує сокет демона
(`src/audio.rs:299-305`). Тест цієї евристики — `src/audio.rs:1083-1095`.

`PIPEWIRE_LATENCY` виставляється глобально через `std::env::set_var`
(у Rust 2024 це `unsafe`, див. SAFETY-коментар `src/audio.rs:761-764`). Для
нашого шляху його читає клієнтська бібліотека PipeWire, до якої підключається
`pipewire-alsa`; значення — прохання, а не гарантія: PipeWire може дати
більший квант, якщо цього хоче драйвер або інший клієнт (`pw-top`: драйвер
бере найменший квант серед підписників).
Користувацьке значення ніколи не перезаписується (`src/audio.rs:317-320`).

### Що насправді означає «буфер» зараз

`BufferSize::Fixed(v)` у нашому vendored cpal — це **період**, а кільце
ALSA — 4 періоди (`vendor/cpal/src/host/alsa/mod.rs:1073-1086`). Коментар
патчу пояснює, чому: upstream робив `v` усім кільцем із періодом `v/4`, і
256 перетворювалося на 64-кадрові колбеки, які рвуться під квантом
PipeWire 1024 і множать накладні витрати плагінів на блок.

Наслідок: `Running::latency_ms()` (`src/audio.rs:360-365`) ділить на частоту
лише один буфер, хоча в черзі їх чотири. UI показує `≈5.3 ms` для
256/48 кГц (`src/ui/settings_ui.rs:1474-1485`), тобто занижує реальну
затримку черги. Це не помилка E1, але після переходу на нативний стрім
цифру треба брати з фактичного кванта й часових міток, а не з налаштування.

Патч підключений як `[patch.crates-io]` у `Cargo.toml:40-44`; у git історії
`vendor/cpal` — один коміт `20b9473` («Add KeyFrameXL codebase…»), тобто це
знімок крейта 0.15.3, а не серія окремих фіксів. Перенести патч на нову
версію вибірково неможливо: або приймаємо upstream-поведінку, або
переписуємо патч заново поверх 0.18.x.

### Помилки, xrun і відновлення

- Патч cpal: `POLLERR` від PipeWire-ALSA (underrun або suspend) раніше
  крутився вічно; тепер це `XRun`/`resume`, а `Disconnected` — помилка
  (`vendor/cpal/src/host/alsa/mod.rs:739-757`).
- Колбек помилки стріму одноразовий: `failed` виставляється один раз, текст
  кладеться в `last_error` (`src/audio.rs:1017-1024`).
- `overruns` — це **не** xrun пристрою, а кількість колбеків, чий час
  перевищив бюджет блоку (`src/audio.rs:993-997`); `load` — згладжене
  завантаження (`999-1000`). Пристроєвих xrun у нас немає взагалі: ALSA їх
  ковтає в патчі.
- `AudioRecovery` (`src/audio.rs:398-556`) — чиста машина станів:
  `Error`, `Stalled` (2 с без колбеків), `PreferredBack`, `DeviceBack`,
  `Retry`; backoff 0.5 → 5 с (`438-443`), опитування пристрою раз на 2 с,
  збереження транспорту. Підключена в `src/ui/settings_ui.rs:116-190`.
- Перепідключення відкриває новий `Audio` цілком (`src/ui/settings_ui.rs:84-99`),
  тому всі черги й плагіни переживають розрив, а позиція відновлюється.

### Вхід для запису

Окремий cpal-стрім: `src/ui/record.rs:57-105`. Бере або збережене ім'я, або
`default_input_device`, відкриває F32 до 2 каналів на **власній** частоті
пристрою (не на частоті проєкту), моно дублює в обидва канали. Тобто запис
уже йде ALSA → PipeWire, з тими самими вадами, що й вихід.

### MIDI (поза обсягом, але є перетин)

MIDI — `midir` поверх ALSA sequencer (`src/midi_in.rs:3`, `451`;
`src/midi_out.rs`). Віртуальні порти для FL Link створюються там же
(`src/fl_link.rs:52-58`). На PipeWire це не впливає, але такі віртуальні
вузли видно як аудіовузли в переліку cpal — див. вимір нижче. MIDI чіпати
не треба; після E1 зміниться лише те, що наші власні вузли треба
відфільтрувати зі списку аудіопристроїв.

## Екосистема

### cpal: релізи після 0.15

| Версія | Дата | Linux-хости | Важливе |
| --- | --- | --- | --- |
| 0.15.3 | 05.03.2024 | ALSA, JACK (feature) | остання «стара» |
| 0.16.0 | 07.06.2025 | ALSA, JACK | RT-пріоритет для ALSA/WASAPI, без нових хостів |
| 0.17.0 | 20.12.2025 | ALSA, JACK | `SampleRate` → `u32`, `Device::id()`, стабільні ID |
| 0.17.3 | 18.02.2026 | ALSA, JACK | остання 0.17 |
| **0.18.0** | **06.06.2026** | **PipeWire, PulseAudio, ALSA, JACK** | нативні хости, єдиний `Error`/`ErrorKind`, `realtime`, стріми не стартують самі, пріоритет хостів PipeWire > PulseAudio > ALSA |
| 0.18.1 | 07.06.2026 | те саме | лише фікс збірки docs.rs |
| **0.18.2** | **16.08.2026** | те саме | xrun через `ErrorKind::Xrun`, імена по портах, фікс rtkit-бурсту, named-стрім не переїжджає сам |
| 0.19 (master) | — | те саме | xrun у `CallbackInfo::xrun()`, `play()` → `start()`, duplex, `stop(timeout)` |

Тобто відповідь на питання «чи є PipeWire у 0.16/0.17» — **ні**. Є тільки
`jack` (0.16/0.17) і `pipewire`/`pulseaudio` з 0.18.0. PR, що додав
PipeWire-хост: [#1093](https://github.com/RustAudio/cpal/pull/1093),
змepжено 02.03.2026 (1598 доданих рядків, 17 файлів).

Ключові зламні зміни для нас (0.15 → 0.18):

- `SampleRate(48_000)` → просто `48_000` (0.17).
- `device.name()` → `device.description()` (людське ім'я) або `device.id()`
  (стабільний ID, `pipewire:<node.name>`); `DeviceDescription` має
  `device_type`, `interface_type`, `address`, `driver`.
- `StreamConfig` передається **за значенням**, а не `&`.
- Усі помилки — `cpal::Error` + `e.kind()`; окремих `BuildStreamError` тощо
  більше немає. Додані `DeviceBusy`, `DeviceChanged`, `RealtimeDenied`,
  `StreamInvalidated`, `Xrun`.
- `build_*_stream()` більше не запускає стрім: потрібен явний `play()`
  (у 0.19 перейменують на `start()`, `play()` поки що deprecated).
- Фіча `audio_thread_priority` → `realtime` (без D-Bus) і `realtime-dbus`
  (з rtkit; на Linux потрібен `libdbus-1-dev`).
- Дефолтна частота тепер 48 кГц, а не 44.1.
- `BufferSize::Default` тепер справді дефолт хоста, а не власні 25/100 мс
  cpal; для ALSA це змінює поведінку.

### Як влаштований PipeWire-хост cpal 0.18.2

- Хост доступний, якщо знайдено сокет (`Host::is_available`); інакше
  `default_host()` іде на PulseAudio/ALSA.
- Пристрої: реальні вузли `Audio/Sink|Source|Duplex` **плюс** синтетичні
  `sink_default`, `output_default`, `input_default`. `id` = `node.name`,
  `description` = `node.description` (локалізована назва).
- `BufferSize::Fixed(n)` → властивість `node.latency = n/rate`
  (`device.rs:172-180`); `n` валідується проти діапазону квантів сервера
  (`min_quantum..=max_quantum`), інакше `UnsupportedConfig`.
- Вхід і вихід групуються `node.group = cpal-<pid>`, щоб граф планував їх в
  одному кванті — важливо для запису під час відтворення.
- RT: окремий потік `cpal_rt_promote` підвищує пріоритет через
  `audio_thread_priority`/rtkit, коли квант змінюється; відмова не валить
  стрім, а приходить як `RealtimeDenied`.
- Часові мітки — з `pw_time` (`now`, `delay`): `playback = now + delay`,
  `capture = now - delay`; це вже готова оцінка затримки графа.
- Стан: `Unconnected` для named-стріму → `DeviceNotAvailable`; помилка
  стріму → `StreamInvalidated`; зміна дефолтного пристрою → `DeviceChanged`
  (через метадані `default`); видалення дефолтного → `DeviceNotAvailable`.
- xrun: читається біт `SPA_IO_CLOCK_FLAG_XRUN_RECOVER` у `process` і
  віддається як `ErrorKind::Xrun` (0.18.2). У 0.19 це переїде в
  `CallbackInfo::xrun()` — точніше, бо прив'язано до конкретного блоку.
- Named-стрім **не** переїжджає на інший пристрій, якщо той зник (свідомо, з
  0.18.2). Отже, наша `AudioRecovery` лишається потрібною.

### pipewire-rs

Офіційні біндинги upstream PipeWire (GitLab `pipewire/pipewire-rs`), крейт
`pipewire` **0.10.1** (19.08.2026), MIT, MSRV 1.80, ~3.7 млн завантажень
усього й ~2.25 млн за останній рік — тобто це не експеримент.

API: `pw::init()`, `MainLoop`, `Context`, `Core`, `registry`, `Stream`
(приклади `audio-playback.rs`, `audio-capture.rs`, `tone.rs`). Формат
узгоджується SPA-подами (`AudioInfoRaw`), буфер береться через
`dequeue_buffer`, час — `stream.time()`, стан — `state_changed`.

Чого крейт **не** дає:

- лічильника xrun (у `spa_io_clock` можна залізти лише сирим FFI);
- підвищення пріоритету потоку (це робить `libpipewire-module-rt` через
  RLIMIT_RTPRIO/portal/rtkit, або сам застосунок через
  `audio_thread_priority`; прапорець `RT_PROCESS` лише переносить `process`
  у потік даних);
- перепідключення: `target.object`/`DONT_RECONNECT`, перестворення стріму —
  на застосунку;
- зручного переліку «пристроїв»: це вузли реєстру, фільтрувати за
  `media.class` треба самому (зате це дає чистіший список, ніж у cpal).

Збірка: `libpipewire-0.3` (у крейті `pipewire-sys` — `system-deps` +
`bindgen`, тобто потрібен ще й `libclang`), версія ≥ 0.3.53 для фіч
`v0_3_53`.

### JACK через pipewire-jack

`pipewire-jack` дає ABI JACK поверх графа PipeWire: застосунок бачить
`system:playback_*`, квант береться з графа, `PIPEWIRE_LATENCY` — лише
підказка, а `node.latency` — «максимальний буфер». Форсувати квант можна
`jack_set_buffer_size()` або `pw-metadata -n settings 0 clock.force-quantum N`.
Пріоритет ниток — `jack.conf`/`module-rt` (`rt.prio`). У cpal для цього є
фіча `jack` (залежність `jack 0.13.5`, збірка потребує
`libjack-jackd2-dev`, рантайм — `pipewire-jack`/`libspa-0.2-jack`).

Для нашого застосунку це гірший UX: у списку пристроїв з'являться JACK-порти
(`system:playback_1`), а не пристрої PipeWire; плюс повний другий аудіошлях
і ще одна залежність. Єдиний сенс — сумісність із користувачами справжнього
`jackd`, яких у 0.2.0 не цілимо.

### Що роблять інші

- **Meadowlark** (Rust-DAW): його команда веде власний крейт `rtaudio`
  (0.8.1, 06.10.2026), у README якого прямо сказано, що причина існування —
  нативний duplex і низька затримка, яких cpal не давав. Це аргумент проти
  cpal *старих* версій, але не проти 0.18: duplex у PipeWire-хості ще в
  драфті, а нам він і не потрібен — у нас окремі вихід і вхід.
- **Helvum** (патчбей PipeWire) — на `pipewire-rs`, але це керування
  графом, не RT-стріми.
- **rodio** — надбудова над cpal, тобто з 0.18 вона теж отримає PipeWire
  без змін у себе.
- **Zrythm** (C), **Helio** (C++), **Ardour** (C++) — не Rust; `dawproject` —
  формат проєкту, не аудіо. Готового Rust-DAW на нативному PipeWire поки
  немає, тож «як у всіх» тут не існує.

### Перевірено на цій машині

PipeWire 1.6.9, cpal 0.18.2, feature `pipewire`, 19.11.2026 (окремий
пробник поза репозиторієм):

- `default_host()` → `PipeWire`.
- Вихід: 5 записів — `default_sink`, `default_output`, вбудована карта,
  `KeyframeXL-FL-link` (сторонній стрім, не наш поточний вузол!),
  Bluetooth-навушники.
- Вхід: 7 записів — серед них `default_sink` і вихідні вузли: cpal навмисно
  виставляє sinks як `Duplex`, щоб можна було писати monitor. Для списку
  мікрофонів це шум.
- `BufferSize::Fixed(256)` → рівно 256 кадрів на колбек, `buffer_size()=256`.
- `Fixed(4096)` → `UnsupportedConfig: not in the supported quantum range
  32..=2048` (діапазон сервера, не наш).
- `pw-cli destroy <node>` під час роботи → рівно одна помилка
  `DeviceNotAvailable`, далі тиша (без циклу помилок).
- `pw-metadata … clock.force-quantum 1024` під час роботи → колбеки стають
  1024, `buffer_size()` теж 1024; після `force-quantum 0` — знову 256.
  Тобто квант може змінитися під нами, і це нормально.
- Вузол у графі: `node.name = pwprobe` (ім'я процесу),
  `media.name = cpal-playback-<pid>`, `node.latency = 256/48000`,
  `node.group = cpal-<pid>`; `application.name` і
  `application.process.binary` — **порожні**.

Останнє важливе для наших скриптів: `scripts/live/listen.sh` шукає вузол за
`application.process.binary`/`application.name` з «keyframexl» — після
переходу на нативний cpal цей фільтр перестане знаходити вузол. Треба
мати `node.name` (для нас — ім'я бінарника) або `media.name` з префіксом
`cpal-`.

## Порівняння

| Критерій | (a) cpal 0.18.2 + `pipewire` | (b) pipewire-rs напряму | (c) cpal `jack` через pipewire-jack |
| --- | --- | --- | --- |
| Квант/затримка | `BufferSize::Fixed` → `node.latency`; фактичний квант може бути більшим; діапазон сервера (32..2048 на тесті); змінюється на ходу | те саме, але можна виставити будь-які props, зокрема `node.lock-quantum`, `node.force-quantum` (обережно — це впливає на весь граф) | квант = квант графа; `jack_set_buffer_size` або `clock.force-quantum`; `PIPEWIRE_LATENCY` лише підказка |
| Імена пристроїв | `description` (локалізована, гарна), `id` = `node.name`; але в списку є чужі стріми, monitor-sinks і дублікати | повний контроль: фільтр за `media.class`, `node.description`, `node.nick`; можна назвати свій стрім «KeyFrameXL» | JACK-порти, не пристрої; для DAW-UI погано |
| Перепідключення | помилки `DeviceNotAvailable`/`DeviceChanged`/`StreamInvalidated`; сам стрім не переїжджає — наша машина лишається | все на застосунку: `state_changed`, перестворення стріму, вибір `target.object` | сервер JACK зник → помилка; перепідключення на застосунку |
| Звіт про xrun | `ErrorKind::Xrun` у 0.18.2 (у 0.19 — `CallbackInfo::xrun()` з прив'язкою до блоку) | немає API; тільки сирий `spa_io_clock` або `pw-top` збоку | `BufferUnderrun` (0.17) → `ErrorKind::Xrun` (0.18) |
| Вхід для запису | є; окремий стрім, `node.group` синхронізує квант; відомий баг із моно-джерелом (#1405) | є, повний контроль над каналами й позиціями | є, JACK-порти входу |
| Ліцензія | Apache-2.0 | MIT | MIT (`jack`), `pipewire-jack` — MIT |
| Залежності збірки | `libasound2-dev` (завжди) + `libpipewire-0.3-dev` + `libclang`; для RT — `libdbus-1-dev` | `libpipewire-0.3-dev` + `libclang`; для ALSA-фолбеку все одно `libasound2-dev` | `libasound2-dev` + `libjack-jackd2-dev`; рантайм `pipewire-jack` |
| Супровід | дуже активний (0.18.x, 0.19 у роботі), але PipeWire-хост молодий (≈5 місяців) | офіційний upstream, стабільні 0.x, повільніший темп | зрілий, але це додатковий шлях |
| Обсяг робіт | ~1–2 дні коду + тести | ~1.5–2 тижні (свій шар стріму, часу, помилок, перепідключення) | ~3–5 днів + нові залежності |
| Ризик для 0.2.0 | середній, локальний | високий: свій RT-аудіокод у релізі | низький технічно, але марний |

Деталі, які варто зважити окремо:

- **cpal 0.18.2 не дає per-stream властивостей.** PR
  [#1329](https://github.com/RustAudio/cpal/pull/1329) (драфт, 19.08.2026)
  додає `node.name`, `node.force-quantum` тощо; поки що їх немає. Отже,
  назвати свій вузол «KeyFrameXL» у мікшері не вийде — буде
  `cpal-playback-<pid>` (PR [#1409](https://github.com/RustAudio/cpal/pull/1409),
  20.10.2026, ще не змерджено, додає `application.name`/`media.name`).
  Для 0.2.0 це косметика; для патчбея — помітно.
- **Баг із моно-входом** ([#1405](https://github.com/RustAudio/cpal/issues/1405),
  18.10.2026): `input_default` завжди звітує 2 канали, а моно-джерело
  підключається лише в `input_FL` — правий канал тихий. Обхід: для
  PipeWire-входу просити 1 канал (наш `record.rs` уже вміє дублювати моно)
  або відкривати реальний вузол джерела, а не `input_default`.
- **Список пристроїв брудний**: чужі стріми, monitor-sinks, дублікати назв
  (вхід і вихід однієї карти звуться однаково). Потрібен фільтр і
  збереження саме `DeviceId` (pipewire + node.name), а не назви.
- **`pipewire-rs` не має xrun** — це головна причина не брати його зараз:
  xrun-лічильник — одна з цілей E1, а писати його сирим FFI заради 0.2.0
  недоцільно.

## Рекомендація

**Варіант (a): cpal 0.18.2 з фічами `pipewire` + `realtime-dbus`, явний
вибір хоста (PipeWire, інакше ALSA), без `pipewire-rs` і без JACK.**

Причини:

1. Уся наша логіка (черги `rtrb`, `ArcSwap`-знімок, `AudioRecovery`,
   збереження транспорту, PDC, метроном) уже живе навколо cpal-стріму.
   Перехід на 0.18 — це заміна ~150 рядків відкриття й кілька дрібних
   API-правок, а не новий аудіошар.
2. cpal дає рівно те, чого бракує сьогодні: нативний вузол у графі,
   `DeviceId` замість ALSA-імен, `Xrun` у колбеку помилки, `DeviceChanged`
   для дефолтного пристрою, RT-пріоритет і часові мітки `pw_time`.
3. `pipewire-rs` виправданий, коли треба свої властивості стріму, фільтр
   вузлів за класом і брендована назва в мікшері. Це наступний крок
   (0.3.0), якщо PR #1329/#1409 не змерджено. Зараз він додав би до релізу
   власний RT-код без xrun-звітності.
4. JACK не дає нічого поверх PipeWire для наших користувачів і додає
   `libjack`-залежність та другий набір імен пристроїв.

Що залишаємо: **ALSA як запасний бекенд** (окремий хост cpal, не патч),
`AudioBackend` для бейджа в UI, `AudioRecovery` без змін логіки.

Що прибираємо: `[patch.crates-io] cpal`, `vendor/cpal`, `PIPEWIRE_LATENCY`
(і `unsafe set_var`), евристику `detect_backend` за іменами.

## Кроки

1. **CI й залежності (першим комітом).** До `.github/workflows/ci.yml`:
   `libpipewire-0.3-dev`, `clang` (для `bindgen` у `pipewire-sys`),
   `pkg-config` уже є; `libasound2-dev` лишається. За бажання —
   `libdbus-1-dev` для `realtime-dbus`. Перевірити, що `cargo check
   --all-targets` проходить на ubuntu-latest (PipeWire 1.0.5 у noble,
   вимога ≥ 0.3.53).
2. **Cargo.** `cpal = { version = "0.18.2", features = ["pipewire",
   "realtime-dbus"] }`; видалити `[patch.crates-io] cpal` і `vendor/cpal`.
   Не використовувати `default_host()` — він тепер сам вибере PipeWire, і
   тоді збережене ALSA-ім'я тихо стане «дефолтом».
3. **Хост.** У `src/audio.rs` додати `fn host() -> cpal::Host`: якщо
   `pipewire_daemon_active()` (`src/audio.rs:299-305`) —
   `host_from_id(HostId::PipeWire)`, інакше `HostId::Alsa`; кешувати в
   `OnceLock` (зараз `output_devices()`/`input_devices()`/
   `Audio::open()`/`record.rs` створюють хост щоразу; на PipeWire це
   реєстровий roundtrip, а recovery опитує пристрої раз на 2 с).
4. **Модель пристрою.** Замість `Option<String>` з ALSA-ім'ям —
   `DeviceEntry { id: String, name: String, backend: AudioBackend }`;
   у `AudioSettings` зберегти `output_id`/`input_id` (з
   `#[serde(alias = "output")]` для міграції). Старі значення
   `default`/`pipewire`/`sysdefault…` → дефолтний вихід PipeWire;
   `hw:`/`plughw:` → ALSA-хост (або дефолт із `fallback = true`, щоб
   спрацював `PreferredBack`).
5. **Фільтр списку.** Показувати лише вузли з `node.name`, що починаються з
   `alsa_output.`/`alsa_input.`/`bluez_output.`/`bluez_input.`, плюс два
   псевдопристрої (`output_default`/`input_default`). Прибрати `cpal-*`,
   наші `kfxl_*` (`KeyframeXL-FL-link`), `.monitor`, дублікати за
   (напрям, `description`). Для входів — не показувати sinks, якщо не треба
   писати monitor.
6. **Відкриття.** `BufferSize::Fixed(n)`: якщо `n` поза
   `SupportedBufferSize::Range` — притиснути до краю й показати фактичне
   значення, а не падати з `UnsupportedConfig` (наші `BUFFERS` аж до 8192,
   а сервер тут 32..2048). Старі API-правки: `SampleRate(rate)` →
   `rate`, `config` за значенням, `device.name()` → `description()`,
   `|e| eprintln!` → `e.kind()`-мапінг, явний `play()`.
7. **Колбек і лічильники.** Уже тримаємо довільний `data.len()`
   (`engine.reserve(128, 8192)`, `src/audio.rs:852`; метроном має 16384
   кадрів, `delayed` коректно пише напряму, якщо блок більший). Додати
   `actual_frames` (ковзне/максимум за секунду) і брати затримку з
   `stream.buffer_size()` + різниці `playback - now`; `Running.buffer`
   оновлювати з фактичного кванта, а не з налаштування. `ErrorKind::Xrun`
   → окремий `xruns: AtomicU32` (не змішувати з `overruns`, це різні речі).
8. **Відновлення.** Мапінг: `DeviceNotAvailable`/`StreamInvalidated` →
   `Reconnect::Error`; `DeviceChanged` для дефолтного стріму → новий
   `Reconnect::DefaultChanged` (перевідкрити, щоб піти за новим дефолтом);
   `RealtimeDenied` → повідомлення в UI, не перепідключення. `Stalled`
   лишити як страховку. Гарантія: перед відкриттям нового стріму старий
   `Audio` дропається (зараз так і є, `src/ui/settings_ui.rs:84-99`).
9. **Запис.** `record.rs`: відкривати вхід через той самий `host()`;
   для `input_default` просити 1 канал і дублювати (обхід #1405), або
   відкривати реальний source-вузол; частоту брати з графа (48 кГц), не з
   «дефолту пристрою».
10. **Прибирання й тести.** Видалити `pipewire_latency_hint`,
    `user_set_pipewire_latency`, `detect_backend` та їхні тести
    (`src/audio.rs:1083-1109`); додати тести: мапінг старих імен у
    `DeviceId`, фільтр списку, клемп буфера, мапінг `ErrorKind` →
    `Reconnect`. Оновити `scripts/live/listen.sh` (шукати `node.name` =
    ім'я бінарника або `media.name` з `cpal-`). Додати `xruns` у Deck і
    Settings поруч з `overruns`.

Порядок безпечний: кроки 1–3 можна зробити й зі старим бекендом, кроки 4–8
— одним комітом, 9–10 — окремо. Гейт релізу: 10 хвилин важкого проєкту на
256 кадрах без жодного xrun, плюс успішний ALSA-фолбек.

## Тестування

**Збірка.** `cargo check --all-targets` на чистій ubuntu-latest з новими
пакетами; окремо `cargo check --no-default-features` (якщо зробимо фічу
`pipewire` опційною) — ALSA-шлях має збиратися без заголовків PipeWire.

**Квант і затримка.**

- `pw-top -b -n 5` під час відтворення: у нашого вузла `QUANT` має
  дорівнювати запитаному (256), `ERR` — 0, `W/Q` — завантаження графа.
- `pw-metadata -n settings` показує `clock.quantum`, `clock.force-quantum`,
  `clock.rate`; змінити `force-quantum` на 1024 і назад — застосунок має
  грати далі, а UI оновити затримку (перевірено: блок змінюється 256↔1024).
- Оцінка згори: `playback - now` з часових міток cpal ≈ `quantum/rate` +
  затримка пристрою; порівняти з тим, що показує Settings.
- Наскрізний round-trip: фізичний loopback (вихід → вхід) і
  `scripts/live/listen.sh` + `scripts/live/measure.py match REC REF` —
  взаємна кореляція дає зсув у семплах; або `jack_iodelay` через
  `pipewire-jack` (він міряє саме вхід→вихід у семплах). Для 0.2.0
  достатньо першого: міряємо «застосунок → монітор sink».

**Underrun-и.**

- 10 хвилин демо-проєкту (багато голосів + плагіни) на 64/128/256/512;
  ціль — 0 xrun на 256, 0 `overruns` після прогреву.
- Порівняти три числа: наш `xruns` (з `ErrorKind::Xrun`), наш `overruns`
  (час колбека > бюджет) і `ERR` у `pw-top`. Розбіжність означає, що
  xrun не доходить до нас або ми рахуємо не те.
- Стрес: `stress-ng --cpu N` на час тесту; перевірити, що RT-пріоритет
  справді взято (`chrt -p <tid>` для потоку cpal) або що в UI є
  `RealtimeDenied`.

**Гаряче від'єднання.**

- `pw-cli destroy <node-id>` (перевірено: одна `DeviceNotAvailable`, далі
  тиша) — застосунок має перевідкритися на дефолті, зберегти позицію,
  повідомити «Audio recovered…».
- USB-вилка/втикання: named-стрім → `DeviceNotAvailable`, потім
  `PreferredBack`, коли пристрій повернеться (опитування раз на 2 с).
- `systemctl --user restart wireplumber` — зміна дефолтного пристрою →
  `DeviceChanged` → перевідкриття на новому дефолті.
- `systemctl --user restart pipewire` — стрім має впасти з
  `StreamInvalidated`/зупинитися; `Stalled` (2 с) — страховка; backoff
  0.5 → 5 с; після рестарту — звук і та сама позиція.
- Після кожного сценарію: `pw-dump` не має показувати двох наших
  `Stream/Output/Audio` (немає витоку стрімів).

**Імена й налаштування.**

- Список виходів: лише реальні пристрої + «Системний вихід»; немає
  `cpal-*`, `kfxl_*`, `.monitor`, чужих стрімів.
- Зберегти пристрій, перезапустити застосунок — вибір той самий
  (`DeviceId`, не назва).
- Старий `settings.ron` з `output: "default"` відкривається без помилки й
  грає через PipeWire.

**ALSA-фолбек.**

- `systemctl --user stop pipewire pipewire-pulse wireplumber` → застосунок
  має відкрити ALSA `default`, бейдж «ALSA», 10 хвилин без рвучих звуків.
- Окремо перевірити 256 і 512: upstream 0.18.2 робить кільце з **двох**
  періодів (`DEFAULT_PERIODS = 2`), а не чотирьох, як наш патч. Якщо 256
  почне рватися — або підняти дефолт для ALSA до 512, або повернути
  патч (уже як свідомий, з тестом).

**Запис і MIDI.**

- Моно-USB-мікрофон: обидва канали не тихі (обхід #1405).
- Від'єднати вхід під час запису — запис зупиняється з помилкою, застосунок
  не падає, повторне підключення відновлює вхід.
- MIDI-клавіатура й FL Link працюють як раніше; переконатися, що
  `KeyframeXL-FL-link` більше не з'являється в списку аудіопристроїв.
