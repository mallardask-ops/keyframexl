# C1 — Пресети Tide

Дослідження до `docs/v0.2.0.md` § C1. Джерела коду: `src/synth.rs`,
`src/engine.rs`, `src/sampler.rs`, `src/fx/*`, `src/preset.rs`,
`src/ui/{welcome,browser,presets_ui,synth}.rs`, `src/render.rs`.
Дата: 2026-11-19.

**Короткий висновок.** Рушій Tide уже дає все, щоб зробити 60–100 пресетів
без жодної правки DSP: 4 таблиці з морфом, адитивний осцилятор, 7-голосий
унісон, саб, шум, LP/HP/BP, два DAHDSR з кривими, glide, 2 LFO (включно з
S&H і синхронізацією), матриця 11×16, 4 макроси й 4 вбудовані ефекти.
Справжні прогалини — не «мало параметрів», а конкретні сімейства: FM, ring
mod, керований sync, паралельний/24 dB фільтр, третій конверт і моно/легато.
Вони блокують частину Bell, FX, Drum-synth і «кислотні» Bass/Lead, але не
заважають зробити 80–90 сильних пресетів. Головна робота C1 — **дані й
метадані**, а не рушій: зараз у пресета немає ні категорії, ні тегів, ні
опису, а заводські пресети взагалі не можна тегувати (у браузері вони
йдуть з `key: None`).

## 1. Можливості Tide

### 1.1 Сигнальний шлях одного голосу

```
Osc A (4 таблиці × 8 кадрів × 7 mip-рівнів, warp)
Osc B (те саме, окремий level/coarse/fine/warp)
Spectral C (1..32 гармоніки, tilt/odd/shimmer)
        + Sub (синус на октаву нижче) + Noise (білий)
        → один TPT SVF (LP | HP | BP, 12 dB/окт)
        → amp env × velocity × 0.3
        → pan (spread унісону)
        → [patch FX: Drive → Chorus → Delay → Reverb] (уже на шині, не per-voice)
```

Ключове в `engine.rs::Voice::render_synth` (287–484): унісон — це `count`
копій A+B з розкидом по висоті й панорамі (314–424), саб — синус із
половиною частоти ноти (312, 452), шум — білий, додається **до** фільтра
(453–456, 473), фільтр — один SVF-банд на голос (41–51), амп — `env ×
vel/100 × 0.3` (469–470).

### 1.2 Параметри

Одиниці й межі взято з `SynthPatch::validate` (`synth.rs:834–896`) та з
обчислень у `engine.rs`, не з UI.

**Осцилятори**

| Параметр | Межі | Значення |
| --- | --- | --- |
| `table` | SineSaw, SquarePulse, Organ, Vowel | 4 хвильові таблиці, `synth.rs:4–11`, 8 кадрів морфу, 7 mip-рівнів (`synth.rs:899–901`) |
| `position` | 0..1 | морф між кадрами таблиці (`synth.rs:987`) |
| `warp` | Bend, Sync, PwmMirror, FmSub | `synth.rs:12–19` |
| `warp_amount` | −1..1 | Bend: phase^2^(2w); Sync: phase×(1+\|w\|×3); PwmMirror: дзеркальна ширина; FmSub: фазова модуляція сабом (`engine.rs:367–386`) |
| `level` | 0..1 | рівень A (0 = вимкнено) |
| `coarse` | −24..24 | півтони від ноти |
| `fine` | −100..100 | центи |
| `osc_b.*` | те саме + `level` | B за замовчуванням вимкнений |
| `spectral.level` | 0..1 | адитивний осцилятор C (`synth.rs:335–410`) |
| `spectral.coarse` | −24..24 | півтони |
| `spectral.partials` | 1..32 | кількість гармонік, обрізається за Найквістом |
| `spectral.tilt` | −1..1 | −1 темний (1/k²), 0 пилка (1/k), +1 рівні партіали |
| `spectral.odd` | −1..1 | −1 лише парні, +1 лише непарні |
| `spectral.shimmer` | 0..1 | кожна гармоніка дихає своїм повільним циклом |

**Мікс і голос**

| Параметр | Межі | Значення |
| --- | --- | --- |
| `sub` | 0..1 | синус на октаву нижче; **не** ділиться на кількість унісону |
| `noise` | 0..1 | білий шум до фільтра |
| `unison` | 1..7 | кількість копій A+B |
| `detune` | 0..1 | ±detune **півтонів** (0.1 = ±10 центів), `engine.rs:337–340` |
| `spread` | 0..1 | панорама крайніх голосів унісону |
| `glide` | 0..10 с | лінійний портаменто (`engine.rs:231–240`) |
| `bend_range` | 0..48 | діапазон pitch wheel |
| `mpe` | bool | MPE на канал |

**Фільтр** (`engine.rs:41–51`, 457–478)

| Параметр | Межі | Значення |
| --- | --- | --- |
| `filter` | LowPass, HighPass, BandPass | один банд SVF, 12 dB/окт |
| `cutoff` | 20..20000 Гц | клампиться до `rate × 0.45` |
| `resonance` | 0..1 | k = 2 − 1.95×res (Q ≈ 0.5…40; res=1 майже самозбудження) |
| `keytrack` | −1..1 | ±1 = 1 окт на окт |
| `env_amount` | −1..1 | ±1 = ±6 октав від Filter Env |

**Конверти** (`sampler.rs:103–194`)

| Параметр | Межі | Значення |
| --- | --- | --- |
| `amp_env`, `filter_env` | Delay/Hold 0..60 с, A/D/R 0..60 с, S 0..1 | DAHDSR |
| `attack_curve`, `decay_curve`, `release_curve` | −1..1 | 0 пряма, + швидко спочатку, − повільно |

**LFO та модуляція** (`synth.rs:39–248`, 785–833)

| Параметр | Межі | Значення |
| --- | --- | --- |
| `lfos[0..2].shape` | Off, Sine, Triangle, Saw, Square, S&H | S&H бере випадкове значення на цикл |
| `rate` | 0.01..30 Гц | вільний режим |
| `sync` + `division` | 1/1, 1/2, 1/4, 1/8, 1/16, 1/32 | від темпу проєкту |
| `retrigger` | bool | фаза 0 на ноту або спільний годинник |
| `mods` | ≤16 маршрутів | 11 джерел × 16 цілей, depth −1..1 |
| джерела | LFO1/2, FilterEnv, Velocity, Macro 1–4, ModWheel, Pressure, Slide (CC74) | `synth.rs:39–80` |
| цілі | Position, Warp, Cutoff, Resonance, Sub, Noise, Detune, Spread, PositionB, WarpB, LevelB, PitchA, PitchB, LevelC, TiltC, OddC | `synth.rs:84–154` |
| `macros[0..3]` | value 0..1, 4 маршрути, depth −1..1 | цілі лише 8 базових параметрів (`synth.rs:815–833`) |

Масштаби цілей: Cutoff — `×2^(d×8)` (depth 0.5 = ±4 окт), PitchA/B — `d×24`
півтонів, решта — додавання в межах 0..1 (`synth.rs:785–813`).

**Ефекти пресета** (`synth.rs:451–466`)

| Слот | Параметри (індекси) |
| --- | --- |
| Drive | Drive 0..48 dB, Tone 500..20000 Гц, Output −24..+6 dB, Mix 0..100% |
| Chorus | Delay 1..30 мс, Depth 0..100%, Rate 0.05..5 Гц, Mix 0..100% |
| Delay | Time 1..16 кроків, Feedback 0..95%, Ping-pong 0..100%, Tone, Wet, Dry |
| Reverb | Size 0..100, Damping 0..100, Width 0..100, Low cut 20..1000 Гц, Wet, Dry |

Порядок фіксований: Drive → Chorus → Delay → Reverb; максимум 4 слоти,
лише ці 4 типи, без плагінів (`synth.rs:884–895`).

### 1.3 Як зараз задані 18 пресетів

- Список — `const PRESETS: [&str; 18]` (`synth.rs:506–525`); звучання —
  `fn factory(index)` з `match` на 18 гілок (`synth.rs:526–731`).
- Гілки **не по порядку**: 16, 17, потім 15 (`667`, `686`, `717`) — дрібна
  пастка супроводу.
- Частина пресетів будується поверх інших: 8→1, 9→2, 10→3, 11→5, 12→3,
  13→4, 14→7, 15→5 (`580–727`). Читати фінальний патч треба «знизу».
- Невідомий індекс повертає Init (`_ => {}`, 728) — при розширенні списку
  помилка індексу не впаде, а тихо дасть синус.
- Немає ні категорії, ні тегів, ні опису: `SynthPreset { name, patch }`
  (`preset.rs:106–111`).
- Користувацькі пресети — плаский каталог `Presets/Synth`, без підпапок
  (`presets_ui.rs:22–42`).
- UI Tide шукає поточний пресет **порівнянням патчів** щоразу за кадр:
  `(0..n).find(|&i| *p == patch_of(i))`, де `patch_of` викликає `factory(i)`
  (`ui/synth.rs:1796–1806`). На 18 пресетах це вже 18 побудов/кадр; на 90
  стане 90 алокацій `Vec` на кадр.

## 2. Прогалини

### 2.1 Чого бракує для «класики»

Спершу — прямо по переліку з задачі: **унісон/detune** є (7 голосів,
±detune півтонів); **supersaw** виходить (7 голосів + spread + chorus);
**саб** є, але фіксований — синус рівно на октаву нижче, без вибору хвилі
й октави; **glide** є (0..10 с, лінійний, без legato-режиму); **шум** є,
але один білий і тільки до спільного фільтра; **wavetables** — не справжні,
а міні-морф 4 таблиць × 8 кадрів; **FM** — лише `FmSub` з фіксованим
ratio; **sync** — лише кратний тембр без керованого slave; **типи
фільтра** — лише LP/HP/BP, 12 dB/окт, один банд.

| Прогалина | Доказ у коді | Що блокує | Обхід зараз | Ціна |
| --- | --- | --- | --- | --- |
| **Справжній FM** | лише `Warp::FmSub`: фаза + `sin(sub)×w×0.25`, модулятор завжди на октаву нижче, без ratio/index/feedback (`engine.rs:385, 414`) | FM-дзвони, Rhodes/Wurli-дзвін, металеві баси, DX-keys, FM-lead | жодного; `Spectral` дає лише гармонічні партіали | середня: додати `fm_ratio`/`fm_index` в `Oscillator` |
| **Керований sync** | `Sync` = `phase×(1+\|w\|×3)`, кратність 1..4 від ноти, без детюну slave (`engine.rs:375`) | sync-lead, sync-sweep, «Screaming Sync» (Welsh), Prodigy-ліди | є sync-тембр, немає sweep | низька: slave-фаза + детюн |
| **Ring mod у патчі** | немає; є лише як мікшерний FX (`fx/mod.rs`) і `VoiceFx` семплера (`sampler.rs:403`) | металеві дзвони, кленґор, робот-FX | мікшерний RingMod (не їде з пресетом) | низька: `ring = A×B`, mix |
| **Паралельний/24 dB фільтр** | один SVF, один банд (`engine.rs:41–51`, 471–479) | acid/303, Moog-бас, агресивні ліди, «formant» FX | LP 12 dB + Drive | середня |
| **Фільтр без drive** | Drive стоїть після всіх голосів, не per-voice (`synth.rs:460–466`) | жирний acid, «growl», перевантажений фільтр | Drive FX (шина) | середня |
| **Третій конверт** | лише amp + filter (`synth.rs:435–436`) | дзвони (удар/корпус/гул окремо), шаруваті drum, гейтовані pad | FilterEnv як другий модулятор, ціною фільтра | середня |
| **Керування ампом з матриці** | цілей `Level A`/`Amp` немає (`synth.rs:84–121`) | trance-gate, tremolo, sidechain-подібні pad | автоматизація в roll/мікшері | низька |
| **Колір шуму / окремий тракт** | один білий шум до спільного фільтра (`engine.rs:453–456`) | хети/тарілки (HP-шум + LP-корпус), snare, «вітер», дихання | level 0 + шум + HP (хети вже виходять) | середня |
| **Моно/легато, режим glide** | поліфонія завжди; glide — лінійний час (`engine.rs:225–240`) | класична моно-фразіровка, legato-портаменто | грати по одній ноті | середня |
| **Третій осцилятор/шум як джерело** | A, B, C(адитив), sub, noise | складні шари, «supersaw + noise» | усе в один фільтр | низька |
| **Wavetable import** | 4 фіксовані таблиці (`synth.rs:899–961`) | PPG-пад, сучасні wavetable-звуки | `position` + `warp` | висока (поза C1) |
| **Випадкове джерело** | `Voice::rnd` існує (`engine.rs:121–122`), але в `ModSource` його немає (`synth.rs:39–49`) | аналоговий дрейф, generative pad, S&H-модуляція позиції | LFO S&H (спільний для всіх нот) | низька |
| **LFO fade-in/delay/one-shot** | `Lfo` має лише shape/rate/sync/division/retrigger (`synth.rs:196–204`) | вібрато «з затримкою», повільні pad-еволюції | retrigger + повільний rate | низька |
| **Макроси на все** | цілі макросів — 8 базових параметрів (`synth.rs:294–305, 815–833`) | macro-morph пресетів, «brightness/space» ручки | немає | низька |
| **Ефекти поза 4 типами** | `FX_KINDS` = Drive/Chorus/Delay/Reverb (`synth.rs:461–466`) | phaser-keys, bitcrush-chiptune, flanger | мікшерні FX (не їдуть з пресетом) | низька-середня |
| **Арпеджіатор** | немає в рушії | справжня категорія Arp | «arp-ready» короткі пресети | висока (поза C1) |
| **Метадані пресета** | `SynthPreset { name, patch }` (`preset.rs:106–111`) | категорії, теги, пошук, обране | немає | **низька — головна робота C1** |
| **Стабільний ключ заводського пресета** | у браузері `key: None` (`browser.rs:826`) | не можна додати в обране чи теги | немає | низька |

### 2.2 Чого **не** бракує (не витрачати час)

Унісон 7 + detune + spread (supersaw, strings, wide pad); саб; білий шум;
LP/HP/BP; два DAHDSR з кривими (pluck, brass, pad, kick); keytrack;
Cutoff/Resonance/Env Amount (acid, wobble); glide (solo, 303); 2 LFO з S&H
і sync (wobble, vibrato, PWM); матриця 11×16 (velocity→cutoff, mod wheel,
pressure); адитивний C (organ drawbars, bells, choir); 4 ефекти (space,
echo, grit).

### 2.3 Які прогалини блокують які категорії

| Категорія | Стан без правок рушія | Що впирається |
| --- | --- | --- |
| **Bass** | 9/10 | acid-303 і справжній growl — 24 dB + per-voice drive; FM-бас — FM |
| **Lead** | 8/10 | sync-sweep, FM-lead; решта (saw, supersaw, square, brass, fifth, PWM, portamento) — є |
| **Pad** | 10/10 | найсильніша категорія; усе є |
| **Keys** | 7/8 | справжній e-piano тільки через FmSub-хак; clav/wurli/organ — є |
| **Pluck** | 8/8 | усе є |
| **Bell** | 6/8 | справжня негармонічність — FM/ring; адитивний C дає гармонічні дзвони |
| **Arp** | 8/9 | сам арпеджіатор — поза Tide; тембри — є |
| **FX** | 7/9 | ring-mod робот, справжній laser — pitch-env є через FilterEnv→PitchA |
| **Drum-synth** | 8/9 | snare/hats — компроміс через один фільтр; kick/tom/clap — є |
| **Chiptune** | 9/9 | усе є (SquarePulse + PwmMirror + S&H + glide) |

Отже: **C1 можна закрити без змін DSP**, але 6–8 пресетів у Bell/FX/Bass
будуть «наближеннями». Якщо хочеться справжніх FM-дзвонів і acid — це
окремі задачі рушія (E-серія), не C1.

## 3. Таксономія і рецепти

### 3.1 Звідки таксономія

- **Surge XT** (15 категорій): Basses, Brass, Chords, FX, Keys, Leads, MPE,
  Pads, Percussion, Plucks, Polysynths, Sequences, Splits, Vocoder, Winds.
- **Vital** (9): Bass, Lead, Keys, Pad, Percussion, Sequence, Experiment,
  SFX, Template; користувачі додають Bells/Plucks/Arps підпапками.
- **Welsh's Synthesizer Cookbook** (102 патерни): strings 17, woodwinds 11,
  brass 7, keyboards 7, voice 5, tuned percussion 7, untuned percussion 11,
  leads 8, bass 8, pads 10, SFX 12.
- **Syntorial** (модулі): базовий звук → cutoff → amp env → doubling →
  filter env → delay → sustain/decay → detune → sub → LFO → resonance →
  mono/poly → unison → reverb → legato/portamento → triangle → chorus →
  mod env → sync → HP/BP → FM → noise → distortion → ring mod → phaser →
  LFO trigger/poly → mod wheel → keytrack → velocity → pitch wheel.
- **C1 у `v0.2.0.md`**: Bass, Lead, Pad, Keys, Pluck, Bell, Arp, FX,
  Drum-synth.

Звідси 10 категорій C1 + Chiptune (окремий жанровий клас, який Tide
покриває ідеально і якого немає в жодній із західних таксономій, бо там
він розчинений у Leads/Keys):

`Bass · Lead · Pad · Keys · Pluck · Bell · Arp · FX · Drum-synth · Chiptune`

(`bright`, `dark`, `wide`, `mono`, `vintage`, `detuned`, `metallic`,
`tempo-synced`, `noise`, `fm`, `sync`, `supersaw`, `808`, `acid`, `lofi`).

## 4. Теги і пошук

### 4.1 Модель даних

Дві незалежні осі — як у Surge/Vital, але з українськими підписами:

1. **Категорія** — рівно одна, фіксований enum (10 значень). Гарантує
   групи в браузері й Welcome, не ламається від синонімів.
2. **Теги** — 0..8 вільних рядків, lowercase ASCII (щоб пошук не залежав
   від мови інтерфейсу): `bright dark warm wide mono detuned metallic
   noise fm sync supersaw 808 acid lofi vintage tempo-synced pluck
   sustained percussive`. Плюс похідні від категорії не дублюємо.

Пропонована структура (у `synth.rs` або новому `src/synth/presets.rs`):

```rust
pub struct PresetMeta {
    pub name: &'static str,
    pub category: Category,   // enum, 10 значень
    pub tags: &'static [&'static str],
    pub desc: &'static str,   // один рядок для підказки
}

pub struct Factory {
    pub meta: PresetMeta,
    pub patch: fn() -> SynthPatch,   // замість match на 90 гілок
}
```

`SynthPatch::factory(i)` лишається як фасад (`FACTORY[i].patch()`), щоб не
чіпати `welcome.rs`, `ui/synth.rs` і тести. Для користувацьких пресетів:

```rust
pub struct SynthPreset {
    pub name: String,
    pub patch: SynthPatch,
    #[serde(default)] pub category: Option<String>,
    #[serde(default)] pub tags: Vec<String>,
    #[serde(default)] pub desc: String,
}
```

`serde(default)` зберігає сумісність зі старими `.kfxsynth`; нові поля
пишуться як є. `VERSION` у `preset.rs` підняти до 2 (старі читаються, нові
у старій програмі вже відхиляються перевіркою `version > VERSION`).

### 4.2 Ключі та обране

Зараз заводський пресет у браузері має `key: None` (`browser.rs:826`),
тому `tag_menu`/`is_favorite` для нього недоступні. Ввести стабільний ключ
`factory:<slug>` (slug від назви, не індекс — індекси зміняться при
розширенні). Для користувацьких лишити шлях файлу. Обране вже зберігається
у `config/keyframexl/browser-tags` (`browser.rs:109–210`) — формат не
змінюється, лише додаються нові ключі.

### 4.3 Пошук

Єдиний матчер для трьох місць (браузер, Welcome, ComboBox у Tide):

```
q → токени (через пробіл)
матч = усі токени входять у (name + category + tags + desc)
     АБО токен є тегом (тоді AND/OR-режим як у наявному tags_section)
```

Додатково — синтаксис як у Surge: `cat:bass`, `tag:acid`, `-tag:fm`
(виключення). Це дешево (рядкові операції) і не потребує індексу на 90
пресетів.

Фасети:

- **Категорія** — рядок чіпів над списком, з кількістю: `Bass 10`,
  `Lead 10`, … (стиль `tags_section`, `browser.rs:873–955`).
- **Теги** — чіпи з `tag_counts`, Any/All.
- **Обране** — окрема поличка `Favorites` (уже є).
- **Останні** — не обов'язково для C1.

### 4.4 UI-точки

| Місце | Зараз | Треба |
| --- | --- | --- |
| Браузер, `synth_presets_section` (`browser.rs:751–845`) | плаский список 18 + Saved, `matches` лише по назві | групи за категорією, чіпи категорій/тегів, пошук по метаданих, ключ `factory:<slug>` для обраного/тегів |
| Welcome, вкладка Tide (`welcome.rs:894–941`) | плаский список, пошук по назві (`904`) | рядок категорій над списком, пошук по тегах/опису, лічильник у чіпі вкладки |

### 4.5 Міграція й сумісність

- **Індекси 0–17 не змінювати.** `welcome.rs:265–266` бере `factory(1)` і
  `factory(3)` для шаблону Tide Studio; тести перевіряють `len == 18` і
  назви (`welcome.rs:1120–1131`). Нові 72 пресети — **дописати в кінець**;
  групування в UI робити за категорією, а не за порядком у масиві.
- Після рефактора на `FACTORY: &[Factory]` тест `len == 18` замінити на
  `>= 90` і перевірку унікальності назв/слагів.
- Старі проєкти зберігають повний `SynthPatch` у собі — вони не залежать
  від індексів. Ризик лише для коду, що викликає `factory(i)`.
- Пресет, збережений у 0.2.0, у 0.1.x не відкриється (version 2) — це
  навмисно і вже оброблено.

- `Song::add_channel`, `Note::new`, `STEP`/`BAR` — побудувати тестовий
  проєкт у 10 рядків (як `welcome::build_tide_preset_song`, але в лібі,
  бо `ui` не входить у `lib.rs`).

### 5.2 Гарнес

Один integration-тест `tests/preset_quality.rs`, який для кожного
`i in 0..FACTORY.len()`:

1. бере `FACTORY[i].patch()`, перевіряє `validate()`;
2. будує `Song`: один synth-канал, нота C4 (60) на 1 такт (~2 с при
   120 BPM), пауза 1 такт, потім акорд C4/E4/G4 по півтакту для перевірки
   поліфонії, і окрема нота C7 (96) на 1/4 такту — для аліасингу на високих
   нотах;
3. рендерить `Tail::Leave`;
4. рахує метрики й порівнює з порогами;
5. пише рядок у `target/preset-report.csv` (для ручного огляду).

Окремий `#[ignore]`-тест (або `src/bin/preset_report.rs`) робить те саме,
але без assert — щоб можна було швидко подивитися таблицю після кожного
бетачу.

### 5.3 Метрики й пороги

| Метрика | Як рахувати | Поріг | Навіщо |
| --- | --- | --- | --- |
| Не тиша | `peak` і RMS по всьому рендеру | `peak ≥ 0.02` (−34 dBFS), `RMS ≥ −45 dBFS` | пресет не «зламався» в беззвуччя |
| Пік | `max\|L\|,\|R\|` | `≤ 0.98` (hard), `> 0.89` — warn | без кліпінгу, з запасом на майстер |
| Гучність | RMS у найгучнішому вікні 200 мс (для `S ≥ .3` — навколо сустейну) | `−22…−14 dBFS` (ціль −18 ±4) | пресети не стрибають на 15 dB |
| DC | середнє L і R за весь рендер і за останні 200 мс | `\|mean\| < 1e-4` (−80 dBFS) | зсув zero-line, «клац» на старті |
| NaN/Inf | `f.is_finite()` для кожного семплу | 0 випадків | рушій обіцяє, тест ловить регресію |
| Denormal | `f.is_subnormal()` для кожного семплу | 0 випадків | див. 5.5 |
| Клік | `max\|x[n]−x[n−1]\|` після атаки | `< 0.7`; warn, якщо > 6× локального RMS | справжня атака — це нормально, «тріщина» — ні |
| Атака | час до 90% від максимуму | `≤ A + 100 мс` | конверт справді працює |
| Сустейн | RMS у вікнах 100 мс на 50% і 90% утримання | різниця `≤ 3 dB` (якщо `S ≥ .3` і нота ≥ 1.5 с) | немає «сповзання» |
| Реліз | вікна 50 мс після gate | монотонно спадає; `< −60 dBFS` за `R×1.2 + 0.2 с` | реліз не обривається і не залипає |
| Хвіст | останні 0.5 с рендера + `channel_activity` | тиша `< −80 dBFS`; рендер не вперся в `MAX_TAIL_SECONDS` (30 с) | немає stuck voices / вічного reverb |
| Стерео | `spread == 0` → `L == R` біт-у-біт; `spread > 0` → кореляція `< .999` | обидва | панорама не «залипла» |
| Детермінізм | два рендери поспіль | біт-у-біт | рушій уже це обіцяє (`engine.rs:129–132`) |
| CPU | `Instant` навколо 512-кадрових блоків `Engine::process` | коефіцієнт реального часу `< 0.5`; warn `< 0.25` | 90 пресетів не мають робити експорт повільним |
| CPU-хвіст | час блоку в тиші після ноти / час блоку під нотою | `< 4×` | denormal-сплеск або самозбудження |

### 5.4 Псевдокод

```rust
// tests/preset_quality.rs
fn song_for(i: usize) -> Song {
    let mut song = Song::default();
    song.instruments.clear();
    let id = song.add_channel(
        "Test",
        InstrumentKind::Synth { patch: SynthPatch::factory(i) },
    );
    song.add_note(1, Note::new(id, 0, BAR, 60, 100));              // 1 такт
    for (k, p) in [60, 64, 67].iter().enumerate() {                // акорд
        let at = BAR + STEP * 8 * k as u64;                        // 2-й такт
        song.add_note(1, Note::new(id, at, STEP * 8, *p, 100));
    }
    song.patterns[0].length = 4 * BAR;                             // місце під хвіст
    song
}

#[test]
fn every_factory_preset_is_audible_clean_and_bounded() {
    for i in 0..SynthPatch::PRESETS.len() {
        let p = SynthPatch::factory(i);
        p.validate().unwrap_or_else(|e| panic!("preset {i}: {e}"));
        let mut frames = render::render_audio(
            &song_for(i), 1, true, render::Tail::Leave,
            &AtomicBool::new(false), &mut |_| {},
        ).unwrap();

        let peak = render::peak(&frames);
        let rms = rms(&frames);                       // свій хелпер
        assert!(peak >= 0.02, "preset {i}: silent");
        assert!(rms >= 10f32.powf(-45.0 / 20.0), "preset {i}: too quiet");
        assert!(peak <= 0.98, "preset {i}: clips at {peak}");
        assert!(frames.iter().all(|f| f[0].is_finite() && f[1].is_finite()));
        assert!(!frames.iter().any(|f| f[0].is_subnormal() || f[1].is_subnormal()));
        assert!(dc(&frames).abs() < 1e-4, "preset {i}: DC");

        envelope_checks(i, &frames, &p);              // атака/сустейн/реліз
        tail_checks(i, &frames);
        if p.spread == 0.0 { assert!(frames.iter().all(|f| f[0] == f[1])); }
    }
}
```

`envelope_checks` рахує RMS по вікнах 50/100 мс і перевіряє таблицю 5.3;
`tail_checks` — останні 0.5 с і `Engine::channel_activity`.

### 5.5 Denormal — окремо

У коді **немає** FTZ/DAZ і немає жодної згадки `denormal`
(`grep -rni "denormal\|flush_to_zero\|MXCSR" src` → порожньо). Reverb —
це Freeverb-комбінатори з feedback (`fx/dsp.rs:111–132`), які після ноти
експоненційно повзуть до нуля й неминуче проходять через f32-денормали;
на x86 це десятки-сотні тактів на операцію. Тому:

- тест **сканує вихід на `is_subnormal()`** і валить пресет, якщо такі є;
- тест міряє час блоку в тиші й порівнює з часом під нотою (`< 4×`);
- виправлення (окремий маленький коміт, не C1): у `Comb::tick`,
  `Allpass` і delay-лініях додати `if y.abs() < 1e-30 { y = 0.0 }`, або
  ввімкнути FTZ на аудіопотоці.

Без цього «автоматична перевірка якості» пропустить реальну проблему:
пресет звучить чисто, але через 8 с хвоста CPU стрибає.

### 5.6 Що тест **не** перевіряє

Музичність, характер, «чи це справді acid». Це закривається лише
прослуховуванням (крок 10). Автотест ловить тишу, кліп, DC, денормали,
зламані конверти й залиплі голоси — тобто все, що легко пропустити очима
в 90 патчах.
