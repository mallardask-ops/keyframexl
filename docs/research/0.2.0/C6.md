# C6 — Посібник користувача (EN/UK)

Дослідження до задачі C6 з `docs/v0.2.0.md`. Стан коду — коміт `d8a7b21`.
Номери рядків наведені для цього коміту; після P1 (локалізація) вони зсунуться.

**Короткий висновок.** Посібник варто робити як **mdBook-книгу в репозиторії**
(`docs/manual/`), англійська — джерело істини, українська — gettext
(`po/uk.po`) через `mdbook-i18n-helpers`. Збірка публікується на GitHub Pages
і **вкладається в релізний tar.gz** для офлайну. `HELP → Manual` зараз
відкриває `docs/manual.md` за шляхом `CARGO_MANIFEST_DIR`
(`src/ui/menu.rs:743-753`) — це працює лише із сорців, тому інтеграцію з
програмою треба переробити разом із C6.

### Що не варто тягнути в посібник

- Архітектурні таблиці модулів, тести й внутрішні команди з `docs/forge.md`
  та `docs/vocal.md` — залишити як developer-документацію, а з посібника
  посилатися на неї лише в розділі «Як це працює» (за бажанням).
- `ui-rules.md`, `dwp-validation.md`, `porting.md`, `roadmap.md` — внутрішні.
- Windows/macOS — навпаки, у посібнику треба **явно** повторити попередження
  про Linux-only (`README.md:54-56`), щоб не було хибних очікувань.

### Пріоритет для 0.2.0

**Обов'язковий мінімум** (без нього C6 не закритий): перший запуск, огляд
інтерфейсу, перший біт, канали, піано-рол, плейліст, мікшер + ефекти, плагіни,
запис, експорт, оновлення, шорткати, troubleshooting.

**Друга хвиля:** поглиблені сторінки семплера, Tide, автоматизації,
FL Link, CLI, файлових форматів, повний довідник 32 ефектів.

### Прогалини й розбіжності (виправити до написання довідника)

1. **`F8`** (пікер) обробляється в `src/ui/mod.rs:2685-2687`, але його немає
   ні в README, ні у вікні шорткатів.
2. **`Ctrl+Shift+M`** (експорт MIDI) є в меню (`src/ui/menu.rs:341`) і в
   обробнику (`src/ui/mod.rs:2607`), але не в списку `F1`.
3. У списку `F1` (`src/ui/menu.rs:799-845`) немає `Alt+E`, `Alt+C`,
   `Alt+↑/↓`, `Alt+Del`, `Ctrl+K`, `Ctrl+A/D/B/C/X/V`, `Ctrl+Shift+Z`,
   `Delete` у Плейлісті, `F8`.
4. Список `F1` каже `Ctrl++`, а реально працює `Ctrl+=` (і egui-зум без
   власного обробника, лише з обмеженням у `src/ui/mod.rs:3313-3319`).
5. Список `F1` — 39 рядків, вшитих у `menu.rs`, **лише англійською**; після
   P1 це або переклад, або джерело розсинхрону.
6. `F2` має два сенси: глобально — перейменувати патерн, у Піано-ролі на
   Vocal-каналі — редагувати лірику. У довідці це треба розділити.
7. `Ctrl+1…0`/`Ctrl+Shift+1…0` працюють лише для перших 10 каналів і лише
   якщо канал існує (`src/ui/mod.rs:2716-2727`).

**Рекомендація:** винести список в один `pub const SHORTCUTS: &[(&str, &str)]`
(з контекстом: global/roll/playlist/rack), рендерити з нього і вікно `F1`,
і сторінку `reference/shortcuts.md` (генерація або тест-звірка). Тоді
документація не розійдеться з кодом, а переклад буде в одному місці.

**Синтез для KeyFrameXL:**

1. Загальна дуга — як у Bitwig: від «що це» до експорту, прогресія від
   простого до складного.
2. Довідник вікон — як у FL: Канали, Піано-рол, Плейліст, Мікшер, Браузер
   мають по одній «канонічній» сторінці, на яку посилаються інші.
3. Наскрізні сценарії — як FL Workflow і Renoise Beginner's Tutorial:
   «перший біт за 10 хвилин», «пісня з вокалом», «звук для гри у Forge».
4. Групування за задачами — як у Renoise: Setup, Song Construction, Mixing,
   Rendering, Shortcuts, FAQ.
5. Кожен скріншот — з підписом і стрілкою/виділенням, як у Surge XT.
6. Обмеження — окремим блоком на сторінці, як `Known Limitations` у
   `docs/vocal.md:59-66`; не ховати їх у виносках.
7. Версія — банер «Посібник для 0.2.0» на першій сторінці; nightly-збірки
   можуть випереджати текст.

### Чому mdBook + gettext

- Один source of truth — англійські `.md`; українська живе в `po/uk.po`,
  а не в копії дерева. `msgmerge` сам позначає застарілі рядки `fuzzy`.
- `mdbook-xgettext` витягує рядки, `mdbook-gettext` підставляє переклад під
  час збірки; для EN достатньо не мати `po/en.po` — книга лишиться
  оригінальною ([USAGE](https://github.com/google/mdbook-i18n-helpers/blob/main/i18n-helpers/USAGE.md)).
- `i18n-report` дає HTML-звіт про стан перекладу — його можна класти в CI
  artifact і показувати в PR.
- Збірка тривіальна: `MDBOOK_BOOK__LANGUAGE=uk mdbook build -d book/uk`.
- GitHub Pages публікується штатним workflow
  ([starter-workflow](https://github.com/actions/starter-workflows/blob/main/pages/mdbook.yml),
  [mdBook CI](https://rust-lang.github.io/mdBook/continuous-integration.html)).

### Де живе й як хоститься

```
docs/manual/
  book.toml            # мова, site-url, тема, preprocessor.gettext
  SUMMARY.md
  GLOSSARY.md          # терміни EN→UK, спільні з UI
  po/
    uk.po
  theme/               # логотип, кольори, посилання на мову
  src/
    README.md
    intro/… sequencing/… sound/… mixing/… audio/… midi/…
    plugins/… interop/… files/… app/… reference/… help/…
    images/…
```

- **Веб:** `https://<org>.github.io/keyframexl/manual/en/` і `/uk/`;
  `[output.html] site-url` обов'язковий, інакше 404-сторінка й CSS ламаються
  на підшляху ([mdBook CI, розділ 404](https://rust-lang.github.io/mdBook/continuous-integration.html)).
- **Офлайн:** у релізний tar.gz додати `docs/manual/en/` і `docs/manual/uk/`
  поруч із `README.md` (розширити `.github/workflows/release.yml:52-56`).
  Це дає посібник без мережі й без залежності від GitHub.
- **Пошук офлайн:** mdBook має fallback через `<script>` для `file://`
  ([issue #972](https://github.com/rust-lang/mdBook/issues/972)), але
  український індекс слабкий — див. ризики.

### Як `HELP` відкриває посібник

Замінити поточний блок `src/ui/menu.rs:743-753` на пошук у такому порядку:

1. `KEYFRAMEXL_MANUAL` (для тестів і розробки);
2. `<тека бінарника>/docs/manual/<lang>/index.html` (релізний tar.gz);
3. `$XDG_DATA_HOME/keyframexl/manual/<lang>/index.html` (майбутні пакунки);
4. `CARGO_MANIFEST_DIR/docs/manual/book/<lang>/index.html` (запуск із сорців);
5. `https://<org>.github.io/keyframexl/manual/<lang>/` (мережа);
6. `README.md` як останній fallback.

`<lang>` береться з `Settings → General → Language` (`Language::English` /
`Language::Ukrainian`, `src/i18n.rs:8-20`), тобто `en`/`uk`. Відкривати
`xdg-open`; помилку показувати в статус-барі, як зараз
(`src/ui/menu.rs:751-753`). Пункт меню має бути в `i18n::Strings`
(`help_manual`, `help_manual_online`) — це частина P1.

Додатково у вікні `F1` зробити кнопку «Повний посібник» → той самий виклик,
щоб користувач не шукав меню.

## Процес перекладу

### Напрямок і джерело істини

- **EN — канонічний текст.** Будь-яка правка сенсу робиться спочатку в
  `src/*.md` (англійською), потім `msgmerge` тягне зміну в `po/uk.po`.
- **UK — переклад UI-термінів із `src/i18n.rs`**, а не довільний. Наприклад,
  у застосунку вже є `Патерн`, `Пісня`, `Плейліст`, `Канали`, `Піано-рол`,
  `Мікшер`, `Браузер` (`src/i18n.rs:216-222`), тому посібник не має вводити
  «рек каналів» чи «рол» як окремі терміни.
- **Не перекладати:** назви продуктів (KeyFrameXL, Tide, Forge, Vocal,
  FL Studio, CLAP, VST, yabridge), шляхи, імена файлів, код, клавіші,
  значення параметрів. Для блоків — `<!-- i18n:skip -->`
  ([USAGE](https://github.com/google/mdbook-i18n-helpers/blob/main/i18n-helpers/USAGE.md)).

### Робочий цикл

```sh
# 1. Джерело → POT
MDBOOK_OUTPUT='{"xgettext": {"pot-file": "po/messages.pot"}}' \
  mdbook build -d po

# 2. Оновити український PO (fuzzy = потребує перегляду)
msgmerge --update po/uk.po po/messages.pot

# 3. Перекласти в Poedit / Weblate / вручну, прибрати fuzzy
# 4. Зібрати обидві мови
mdbook build -d book/en
MDBOOK_BOOK__LANGUAGE=uk mdbook build -d book/uk

# 5. Перевірки
msgfmt --check --statistics -o /dev/null po/uk.po
msgattrib --untranslated --no-obsolete po/uk.po   # має бути порожньо
```

Ключ `pot-file` — з `mdbook-i18n-helpers` 0.4.0; для іншої версії звірити з
README/CHANGELOG. Після оновлення самих helpers один раз запускати
`mdbook-i18n-normalize po/uk.po`. Версії `mdbook` і helpers пінити парою й
перевірити сумісність на першій збірці — інакше CI може зламатися під час
оновлення одного з них.

### Синхронізація EN↔UK

1. **Один PR — обидві мови.** Якщо змінений англійський абзац, у тому ж PR
   оновлений `po/uk.po` (або явний `fuzzy`, якщо переклад доробить інша
   людина). PR без PO-оновлення не проходить рев'ю.
2. **`fuzzy` ≠ готово.** `mdbook-gettext` для fuzzy показує англійський
   оригінал; CI має падати або попереджати, якщо fuzzy > 0.
3. **Звіт перекладу** (`i18n-report`) — артефакт CI і посилання в PR:
   видно відсоток і сторінки, що відстали.
4. **Глосарій — закон.** `GLOSSARY.md` фіксує ~20 термінів; зміна терміна в
   UI (P1) і в посібнику — один PR.
5. **Скріншоти — по мові.** Текст на скріншоті має збігатися з мовою
   сторінки. Якщо перезняти дорого — краще нейтральний кадр без підписів,
   ніж англійський UI на українській сторінці.
6. **Рев'ю:** носій української перевіряє не лише орфографію, а й терміни,
   рід/відмінки (uk has 3 plural forms), тире й лапки за стилем репо.
7. **Машинний переклад** — лише як чернетка; після нього обов'язкове ручне
   редагування (USAGE прямо попереджає про `cloud-translate`).
